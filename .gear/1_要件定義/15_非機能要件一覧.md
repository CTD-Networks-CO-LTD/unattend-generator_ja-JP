# 非機能要件一覧

本一覧は、Windows 無人セットアップ応答ファイル生成システム（`unattend-generator_ja-JP`）における非機能要件を定義したものです。

| 要件ID | カテゴリ | 非機能要件項目 | 目標値・設計基準 | 検証方法・担保手段 | 優先度 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **NFR-001** | 性能・効率性 | クライアントサイド応答ファイル（XML）の即時生成性能 | ダウンロードボタン押下後、XMLNode シリアライズおよび Blob 生成処理が **1秒以内** に完了すること。 | 各主要ブラウザ（Chrome, Edge, Firefox, Safari）での自動実行計測テスト | 高 |
| **NFR-002** | 性能・効率性 | クライアントサイド ISO 9660 生成時のメモリ（ヒープ）消費抑制 | 大容量設定（AppLockerPolicy等）が含まれる場合でも、ブラウザのヒープ消費量を **50MB以下** に抑え、フリーズを防止すること。 | Chrome DevTools メモリプロファイラおよび E2E テスト（`test_e2e_engine.py`） | 中 |
| **NFR-003** | 性能・効率性 | 日本語キーボード設定レジストリ適用のオーバーヘッド最小化 | WinPE および `specialize` フェーズでの `kbd106.dll` 等のレジストリ書き換え処理が、インストール全体の所要時間に与える影響を **1秒未満** に抑えること。 | 仮想マシン（Hyper-V / VMware）でのクリーンインストール実測検証 | 高 |
| **NFR-004** | 性能・効率性 | サーバーレスAPI（Cloudflare Workers）の応答速度 | サーバーレスエンドポイント経由での XML / ISO 生成リクエスト処理時間を、平均 **200ms以内**（ネットワーク遅延除く）とすること。 | CI環境からの API ベンチマークテスト（`verify_deployed_sites.js`） | 中 |
| **NFR-005** | セキュリティ | 完全ローカル処理による機密情報漏洩防止 | クライアント生成モード時、入力された管理者パスワード、プロダクトキー、Wi-Fi暗号化キー等の機密情報を外部ネットワークへ一切送信しないこと。 | ブラウザ DevTools ネットワークログ監視および E2E 通信遮断テスト | 高 |
| **NFR-006** | セキュリティ | セットアップ完了後の機密情報ファイル残存防止 | 初回自動ログオン完了後、インストール用媒体で保持していた `unattend.xml` および `Wifi.xml` をOSローカルディスクから完全消去すること。 | インストール完了直後の OS ファイルシステムスキャンテスト | 高 |
| **NFR-007** | セキュリティ | アカウントセキュリティ・ロックアウト構成の実効性保証 | 無人セットアップ適用時、パスワード有効期限無制限およびロックアウト閾値が OS 初期起動時に確実に有効化されていること。 | OS起動後の `net accounts` コマンド実行結果検証 | 高 |
| **NFR-008** | 可用性・信頼性 | 静的ホスティング（GitHub Pages）の稼働安定性 | GitHub Pages のインフラ稼働率（99.9%以上）に準拠。本番リリースサイト（`/`）とプレビューサイト（`/preview/`）が常時アクセス可能であること。 | 外形監視テストおよび HTTP 200 応答チェック | 中 |
| **NFR-009** | 可用性・信頼性 | サーバーレスAPI障害時の自動クライアントフォールバック | サーバーレスAPIがネットワーク障害等でダウンした場合、自動的にクライアントサイド生成エンジンへ切り替わり、ダウンロードを継続できること。 | API エラー時のフォールバック E2E シミュレーションテスト | 中 |
| **NFR-010** | 保守・運用性 | JavaScript と C# エンジンのパリティ（等価性）自動検証 | C#側とJS側の双方から出力される XML ノード構成が、同一入力パラメータに対し **完全一致（差分0バイト）** することをCI上で常時保証すること。 | 自動パリティテスト（`test_engine_parity.js`, `test_feature_parity.js`） | 高 |
| **NFR-011** | 保守・運用性 | 新規 Modifier 追加時の自動乖離検知（パリティ検査） | 新規の構成機能（Modifier）がC#またはJSの片方のみに追加された際、`sync_modifiers.js --check` により 100% ビルド前エラーとして検知できること。 | GitHub Actions（`verify-engine.yml`）の自動実行 | 高 |
| **NFR-012** | 保守・運用性 | CI/CD パイプライン実行速度の高速化 | GitHub Actions 上での C# ビルド、JS パリティテスト、静的アセット生成ワークフローの総実行時間を **3分以内** に完了させること。 | GitHub Actions ワークフロー実行時間の継続監視 | 高 |
| **NFR-013** | 互換性・移行性 | C# クラスライブラリの .NET 10 / C# 13 互換性維持 | .NET 10 環境をターゲットとし、主要依存ライブラリ（`Newtonsoft.Json` 等）とともに警告・エラーなくビルド・テスト通過できること。 | `dotnet test` および dotnet.yml ワークフロー | 高 |
| **NFR-014** | 互換性・移行性 | 主要ブラウザおよびマルチデバイス環境対応 | Chrome, Edge, Firefox, Safari（最新版）において等価に動作し、デスクトップ・タブレット・モバイルの各画面解像度でレイアウト崩れがないこと。 | クロスブラウザ動作テスト（Playwright / Pythonスクリプト） | 中 |
| **NFR-015** | 拡張性 | 本家（Schneegans版）UI・ロジック構造の継続的追従性 | 本家リポジトリに変更があった際、`sync-upstream` ワークフローにより自動で差分を検出し、同期プルリクエストが起票されること。 | 定期実行 GitHub Actions（`sync-upstream.yml`） | 中 |
