# プロジェクト概要

## 1. システム概要
`unattend-generator_ja-JP` は、Windows 10 / Windows 11 の自動インストール（無人セットアップ / クリーンインストール）に使用する応答ファイル `autounattend.xml` および仮想ブートメディア `autounattend.iso` を、Webブラウザ上（クライアントサイド）および .NET 環境で高速・安全に生成するためのオープンソースツールです。

本プロジェクトは、グローバル標準として広く利用されている Christoph Schneegans 氏の「[unattend-generator](https://github.com/cschneegans/unattend-generator)」をベースにフォークし、**日本国内のエンタープライズおよび個人ユーザー向けに特化したカスタマイズ（日本語106/109キーボード、ja-JPロケール、日本時間タイムゾーン、IME、日本語環境特有のレジストリ最適化など）** を施したプロジェクトです。

---

## 2. 開発の背景と課題
Windows のクリーンインストール時に使用する自動応答ファイル（`autounattend.xml`）は、Microsoft 公式ツール（Windows System Image Manager: WSIM）で作成すると大容量の ADK インストールが必要であり、設定項目が膨大かつ複雑で設定ミスを誘発しやすいという課題がありました。

また、本家 Schneegans 版のジェネレーターは非常に優れているものの、以下のような日本固有の運用課題が存在していました：
1. **キーボード配列の不整合**: 日本語106/109キーボードを選択しても、WinPE フェーズや初回ログオン時のレジストリ設定（`kbd106.dll`、`PCAT_106KEY`、タイプ7/サブタイプ2）が不十分で、英語101キーボードとして誤認識されるケースがある。
2. **日本固有の環境設定**: ロケール（ja-JP）、タイムゾーン（Tokyo Standard Time）、言語パック、システム国際設定のコピーがワンストップで構成しにくい。
3. **サーバー不要のセキュリティ担保**: 企業のキッティング現場で利用する際、プロダクトキーやWi-Fiパスワード、管理者パスワード等の機密情報が外部サーバーへ送信されるリスクを排除した「完全ローカル（クライアントサイド完結）処理」への需要。

---

## 3. 主要な特徴とソリューション

### (1) 完全クライアントサイド処理による機密情報保護
Webブラウザ上で動作する Vanilla JavaScript 製エンジン（`UnattendEngine`）により、サーバーへの通信を一切行わずにブラウザのメモリ内だけで `autounattend.xml` および ISO 9660 準拠の仮想メディア（`autounattend.iso`）を即座に生成・ダウンロードできます。入力した機密情報（パスワードやWi-Fiキー）が外部ネットワークに漏洩しません。

### (2) 日本語環境（ja-JP）への完全最適化
- **日本語キーボード完全対応**: WinPEフェーズでの LayeredDriver 割り当て（`1`）、および `specialize` / `firstLogon` フェーズでのレジストリ書き換えにより、日本語106/109配列をOS起動直後から確実に永続化。
- **システム国際設定の自動同期**: `New-WinUserLanguageList` と `Copy-UserInternationalSettingsToSystem` による言語リストおよびシステムアカウントへの言語同期。

### (3) C# コアライブラリと JavaScript エンジンのパリティ（等価性）保証
- サーバー／CLI環境で利用可能な C# クラスライブラリ（.NET 10 / C# 13）と、ブラウザで動作する JavaScript エンジンが 1対1 のモジュール構造で設計されています。
- 自動パリティ検証テスト（`test_engine_parity.js`, `test_feature_parity.js`）および差分検知スクリプト（`sync_modifiers.js`）により、両エンジンの出力 XML が文字・バイト単位で 100% 一致することを CI/CD パイプライン上で常時保証します。

### (4) 堅牢な CI/CD 自動化とマルチ環境ホスティング
- GitHub Actions により、C# ビルド・ユニットテスト、JSパリティテスト、モジュール自動バンドル（`build_engine.js`）、GitHub Pages への静的ホスティングが完全自動化されています。
- 本番リリース環境（`/`）と、最新開発ブランチを即時プレビューできる環境（`/preview/`）が論理分離されています。
- 必要に応じて Cloudflare Workers などのサーバーレス環境で API として稼働させることも可能です。

## 4. 用語定義

| 用語 | 説明 |
| :--- | :--- |
| **autounattend.xml** | Windows セットアップの起動時（WinPE）に読み込まれ、GUI画面をスキップしてインストールを自動実行するための XML 応答ファイル。 |
| **Pass (セットアップパス)** | Windows セットアップの処理ステージ。`windowsPE`, `offlineServicing`, `generalize`, `specialize`, `auditSystem`, `auditUser`, `oobeSystem` の7段階からなる。 |
| **Modifier** | 応答ファイルの特定領域（コンピューター名、ディスク、ロケール、ブロートウェア等）を組み立てる個別の設定モジュール（C#クラスおよびJSクラス）。 |
| **GenerationContext** | 画面から入力されたフォーム値（FormData）を保持し、各 Modifier にデータを提供するとともに、XMLノードやスクリプトを蓄積する生成コンテキスト。 |
| **XmlNode** | 応答ファイルの階層構造をメモリ上で表現し、整形式の XML 文字列へシリアライズする軽量クラス。 |
| **PowerShellSequence** | セットアップの各フェーズ（`specialize`, `firstLogon`, `userOnce`, `defaultUser` 等）で実行する PowerShell スクリプトを順序正しく連結・管理する仕組み。 |
| **Bloatware（ブロートウェア）** | OSにプリインストールされている不要なアプリ群（Teams, OneDrive, Copilot, Bing, Xbox等）。 |
| **Parity（パリティ）** | C# エンジンと JavaScript エンジンが出力する XML の完全一致（バイト精度）の等価性。 |
