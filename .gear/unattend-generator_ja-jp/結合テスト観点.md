# 結合テスト観点

## テスト観点ツリー

### ITV-L1-001 DB結合

#### ITV-L2-001 SQL結合・検索 (生成コンテキスト履歴管理機能)

- **ITV-L3-001 履歴一覧検索とフィルタ条件の検証** [高]
  - GET /api/v1/generator/contexts 実行時に generation_contexts テーブルから対応データが正しく取得できること
  - プロセッサアーキテクチャ(ProcessorArchitecture)やロケール(Locale)による絞り込みフィルタが機能すること
  - 指定されたソート条件およびページネーション（OFFSET, LIMIT）がSQLに適用され、正しく順序制御されること

#### ITV-L2-002 トランザクション制御 (生成コンテキスト履歴管理機能)

- **ITV-L3-002 生成コンテキスト新規作成時のコミット・ロールバック** [高]
  - POST /api/v1/generator/contexts 実行時に generation_contexts テーブルへデータが正常コミットされること
  - アカウント設定等の関連データ登録でエラーが発生した場合に、一連のINSERT処理がロールバックされること
  - UUIDが正常に自動生成され、generation_contexts のプライマリキーとして一意に登録されること

#### ITV-L2-007 SQL結合・関連データ整合性 (生成コンテキスト・アカウント情報管理)

- **ITV-L3-009 generation_contextsとaccountsテーブルの外部結合・マッピング検証** [高]
  - generation_contextsのIDを指定して詳細取得(GET)する際、紐付くaccountsレコード（最大10件）が外部結合により正しいパラメータ（表示名、グループ、パスワード等）で一括取得されること
  - accounts側に該当コンテキストに紐付くレコードが存在しない（0件）場合でも、エラーにならず空配列として親のgeneration_contextsデータが問題なく返却されること
  - セキュリティポリシー（PasswordExpirationMode, LockoutMode等）の拡張パラメータが、generation_contextsテーブル内の対応カラムから整合性を持って取得されレスポンス構造にマッピングされること
- **ITV-L3-010 新規アカウント設定追加時の外部キー制約および重複防止検証** [高]
  - POST /api/v1/generator/contexts/{id}/accounts実行時、指定したコンテキストIDがgeneration_contextsテーブルに存在しない場合、外部キー制約違反（400 / 404エラー）として正しくハンドリングされること
  - 同一コンテキストID配下に、既に登録されているアカウント名と完全に同一のアカウントを追加しようとした際、ビジネスルール（アカウント名重複エラー）により弾かれ、accountsテーブルに重複インサートされないこと
  - Unattendedアカウントとして新しく登録されたアカウントが、パスワード難読化（ObscurePasswords）フラグや割り当てグループ（Administrators/Users）を保持して正しくaccountsテーブルに書き込まれること

#### ITV-L2-008 トランザクション制御・物理削除影響 (生成コンテキスト削除・更新処理)

- **ITV-L3-011 コンテキスト削除時のカスケード削除およびコミット/ロールバック動作** [高]
  - DELETE /api/v1/generator/contexts/{id}を呼び出した際、トランザクション制御のもとで親レコード（generation_contexts）と紐付く子レコード（accounts）が同時にカスケード物理削除されること
  - 削除中にエラーまたはシステムクラッシュ等が発生した場合、処理全体がロールバックされ、削除対象のgeneration_contextsおよびaccountsが未削除の整合性を保った状態で残留すること
  - 物理削除が完全にコミットされた後、再度のGETリクエストに対して404エラー（該当コンテキスト不在）が正しく返却され、関連テーブルにゾンビレコードが存在しないこと
- **ITV-L3-012 更新処理における楽観排他制御およびトランザクション処理** [中]
  - PUT /api/v1/generator/contexts/{id}呼び出し時、同時リクエストによるコンティニュアス更新に対して、排他制御（バージョン管理等）による不整合防止が動作すること
  - 複数のパラメータ（プロセッサアーキテクチャ、コンピュータ名、セキュリティ設定等）を同時にPUT更新した際、単一トランザクション内で全て正常に適用されるか、または全体がロールバックされること
  - accountsテーブルを含む連動データ更新において、一部のアカウント設定更新がスキーマエラーとなった場合、generation_contexts側の基本情報更新も完全にロールバックされること

#### ITV-L2-012 トランザクション制御 (生成コンテキスト管理・統計機能)

- **ITV-L3-017 生成コンテキスト登録時のトランザクション整合性** [高]
  - POST /api/generation-contexts 実行時に generation_contexts テーブルへデータ登録がコミットされること
  - 登録処理中に想定外のエラー（NW遮断等）が発生した場合、データ登録がロールバックされ不完全なコンテキストが残存しないこと
  - 同一リクエストパラメータによる重複登録時、一意性制約エラーとなりトランザクションが正しくロールバックされること

#### ITV-L2-013 データ整合性 (コンテキスト管理テーブル群)

- **ITV-L3-018 保存パラメータのテーブル格納検証** [高]
  - FormData から抽出した ProcessorArchitecture などの設定値が、対応する generation_contexts テーブルの各カラムに正確なデータ型で保存されること
  - テーブル定義で定義された必須カラムが Null の場合、データベースの制約により正しくエラーを検知・ハンドリングできること
  - 文字数制限（コンピューター名の15文字制限等）を越える値がテーブル書き込み時にバリデーションされ、DB型エラーを未然に防止できること

#### ITV-L2-014 SQL結合・検索 (システムレポート集計処理)

- **ITV-L3-019 統計レポート用データ集計SQL検証** [中]
  - GET /api/v1/generator/stats 呼び出し時、generation_contexts テーブルから正確な集計期間のレコードのみが抽出されること
  - 集計対象のレコードが 0 件の場合、システムエラーを発生させずに空（または初期値 0）の統計結果を応答すること
  - 複数アカウント（accountsテーブル等）が紐付いているコンテキストに対し、重複カウントされることなく集計が行われること

#### ITV-L2-021 データ整合性・関連データ連携 (生成コンテキスト管理API / ユーザーアカウント管理API)

- **ITV-L3-028 外部キー制約とカスケード削除の挙動検証** [高]
  - generation_contextsテーブルのレコードを削除した際、紐付くaccountsテーブルのレコードがカスケード物理削除されること
  - 存在しないgeneration_contextsのidを親としてaccountsレコードをPOST登録しようとした際に、外部キー制約によりエラーとなること
  - accountsレコードの更新(PUT)時に、関連するgeneration_contextsテーブルの外部キー関係に矛盾が生じないこと
- **ITV-L3-029 排他制御（楽観ロック／悲観ロック）** [中]
  - 同一のgeneration_contextsのidに対して同時にPUT更新を実行した際、後から実行したリクエストが排他エラーとなること
  - 更新API実行中に別スレッドからGET詳細取得を実行した際、コミット前の不整合な中間データ（ダーティリード）が取得されないこと
  - 排他エラー発生時にロールバックが正常に行われ、データベース内の既存レコードが変更されないこと

#### ITV-L2-022 トランザクション制御 (ユーザーアカウント管理API)

- **ITV-L3-030 アカウント追加・更新時のコミットおよびロールバック動作** [高]
  - 同一アカウント名重複検証エラー（BP-006）などビジネスルール違反が発生した場合、処理全体がロールバックされテーブルに変更が反映されないこと
  - 正常なアカウント情報が登録された場合、トランザクションが正常コミットされ、同一コネクション外からも即座に参照可能となること
  - 更新処理中にDBセッション切断やタイムアウトが発生した場合、自動ロールバックされ中途半端なデータが残らないこと

#### ITV-L2-026 関連データ整合性・トランザクション制御 (ユーザーアカウント制御機能)

- **ITV-L3-036 アカウント設定の物理削除時の整合性確認** [高]
  - 指定したコンテキストIDおよびアカウントIDに対応するレコードが、accountsテーブルから正しく物理削除されること
  - 存在しないIDを指定した場合にDBエラー等にならず、APIから適切なエラーレスポンス（404等）が返却され、他のレコードが変更されないこと
  - 同一コンテキストに属する他のアカウントレコードが削除されず、指定レコードのみが正常に削除されること

#### ITV-L2-038 SQL結合・検索 (サーバーサイド API を介した自動応答ファイル生成機能)

- **ITV-L3-052 generation_contextsのパラメータ読み出し・復元整合性** [高]
  - クエリパラメータで指定されたコンテキストIDを基に generation_contexts テーブルから対象データが正しく検索されること
  - 言語ロケール(ja-JP)やキーボード設定、BypassRequirementsCheck 等の構成値が破損せずにXML生成パイプラインへ受け渡されること
  - DB上のデータと生成エンジン（xml_node.js）の間でデータ型の暗黙変換エラーが発生しないこと

### ITV-L1-002 API結合

#### ITV-L2-003 認証・認可制御 (認証・セッション管理機能)

- **ITV-L3-003 ログイン認証およびトークン発行検証** [高]
  - POST /api/v1/auth/login に有効な管理者資格情報を送信した際、200 OK とアクセストークンおよびリフレッシュトークンが返却されること
  - 誤った資格情報を送信した場合に 401 Unauthorized エラーとなり、レスポンスにトークンが含まれないこと
  - 無効なリフレッシュトークンで POST /api/v1/auth/refresh を実行した際、401 Unauthorized エラーが返却されること
- **ITV-L3-004 履歴一覧取得時の認可権限検証** [高]
  - 有効な Bearer トークンかつ generator:read 権限がある場合のみ GET /api/v1/generator/contexts が 200 OK を返却すること
  - Bearer トークンが欠落している場合に 401 Unauthorized エラーが返却されること
  - トークンは有効だが generator:read 権限を保持しない場合に 403 Forbidden エラーが返却されること

#### ITV-L2-004 異常系パラメータ・バリデーション (生成コンテキスト履歴管理機能)

- **ITV-L3-005 構成パラメータの境界値および必須チェック** [中]
  - POST /api/v1/generator/contexts 実行時に、必須パラメータが欠落している場合に 400 Bad Request と適切なエラーコードが返却されること
  - ProcessorArchitecture 等のパラメータに規定値（amd64, x86, arm64）以外の不正な文字列を設定した場合、バリデーションエラーとなること
  - パスワードを難読化(ObscurePasswords)するフラグ等の boolean 項目に文字列を渡した際、適切にエラーハンドリングされること

#### ITV-L2-009 異常パラメータ・バリデーション連携 (自動応答ファイル統合生成機能・バリデーター群)

- **ITV-L3-013 自動応答ファイルプレビュー構築APIでのスキーマ・ビジネスルール検証** [高]
  - POST /api/v1/generator/buildに渡されたパラメータにおいて、必須となるプロセッサアーキテクチャ(ProcessorArchitecture)が存在しない場合に400エラーが返却されること
  - 設定されるコンピューター名（ComputerName）が15文字を超えている、またはホワイトスペースや無効な記号文字（{ }, [ ], \, ^, %, 等）が含まれる場合に、ConfigurationExceptionに類する形式で適切にエラー応答されること
  - 自動サインオンが有効、かつ機密ファイルの削除を行う場合に、構成アカウント群に管理者アカウント（Administrators）が最低1つ定義されているかをAPIバリデーターにて検知・ハンドリングできること

#### ITV-L2-010 ステータスコード・認証認可 (セキュリティ制限およびステータスハンドリング)

- **ITV-L3-014 特定APIにおけるBearer Token認証・認可境界検証** [高]
  - DELETE /api/v1/generator/contexts/{id}に対して有効なトークンを持たずにリクエストした場合、一貫して401 Unauthorizedエラーが返却されDBへのアクセスが発生しないこと
  - 認可権限スコープが不足しているトークン（例: read専用スコープのみ）で削除APIを実行した場合、403 Forbiddenエラーが正確に返却されること
  - 認可成功時にサーバーのバックエンドから正しい正常終了コード（200 OK または 204 No Content）が返されること

#### ITV-L2-015 HTTPメソッド別動作・ステータスコード (応答ファイル・ISO生成API群)

- **ITV-L3-020 POST /api/v1/generator/download の応答制御** [高]
  - 正常に autounattend.xml のビルドが完了した場合、HTTPステータス 200 と適切な Content-Disposition ヘッダーが返却されること
  - パラメータ不正やビルドエラー時（ConfigurationException等）、対応する異常系の HTTPステータスコードおよびエラーメッセージが返却されること
  - OPTIONSメソッドによるプリフライトリクエストに対し、CORSヘッダー（Access-Control-Allow-Origin: *）を含む正しい応答が返ること
- **ITV-L3-021 POST /api/v1/generator/iso のバイナリ配信検証** [高]
  - 正常レスポンスとして、MIMEタイプ「application/x-iso9660-image」がレスポンスヘッダーの Content-Type に設定されていること
  - 生成パラメータ（formData）に基づき、バックエンドで作成された ISO Blob のバイトサイズが正常にヘッダーに設定されていること
  - 生成エラー発生時に、バイナリ破損応答ではなく適切なJSON形式のエラーメッセージが返却されること

#### ITV-L2-016 異常パラメータ・バリデーション (入力バリデーション連携処理)

- **ITV-L3-022 リクエストパラメータの境界値およびスキーマ検証** [高]
  - POST /api/generation-contexts へのリクエストに必須の ProcessorArchitecture が欠落していた場合、バリデーションエラーを検知して 400 Bad Request を返すこと
  - コンピューター名に無効な特殊記号（{ }, [ ], \, ^, %, などの特殊文字群）が入力された場合、API結合境界でエラー応答すること
  - 同一リクエスト内で管理者アカウントが定義されていない自動ログオン設定が送られた場合、ビジネスルール不整合エラーが返却されること

#### ITV-L2-023 HTTPメソッド・パラメータ整合性 (生成コンテキスト管理API / ユーザーアカウント管理API)

- **ITV-L3-031 セキュリティ設定パラメータ拡張検証** [高]
  - GET /api/generation-contexts/{id} のレスポンスに、追加されたPasswordExpirationModeやLockoutModeのパラメータが正しく紐付けられて返却されること
  - PUT /api/generation-contexts/{id} 時にセキュリティ維持設定（機密情報ファイル削除有無など）を含む新規拡張パラメータが、検証ルールを通過して保存できること
  - 型不正なパラメータ値（LockoutModeに定義外文字列など）を入力した際、API側で400 Bad Requestのエラーが返却されること
- **ITV-L3-032 アカウント登録制約・重複バリデーション** [高]
  - POST /api/generation-contexts/{id}/accounts 実行時に、同一アカウント名がすでに定義されている場合に重複エラー（ConfigurationException想定のHTTPレスポンス）が返却されること
  - 作成するアカウントに「Administrators」（管理者グループ）が含まれない状態で、自動ログオン（AutoLogon）が有効にされた場合、相関チェックによりエラーとなること
  - アカウント名に空白が含まれるなど、命名規則制限（15文字制限、無効記号文字除外）を逸脱した場合に適切にエラー応答すること

#### ITV-L2-024 認証・認可制御 (生成コンテキスト管理API / ユーザーアカウント管理API)

- **ITV-L3-033 Bearerトークン検証および未認可操作防止** [高]
  - 各APIリクエスト時に、Authorizationヘッダーに有効なBearer Tokenが含まれていない場合、401 Unauthorizedが返却されること
  - 異なるテナントや所有者以外のGenerationContextに対して、GET詳細取得やPUT更新、アカウント追加を試行した際、403 Forbiddenなどの権限チェックエラーとなること
  - 有効期限切れのアクセストークンを送信した場合、認証エラーが返却されAPI処理が遮断されること

#### ITV-L2-027 HTTPメソッド別動作・ステータスコード検証 (アカウント設定削除・バリデーターAPI群)

- **ITV-L3-037 DELETEメソッドによるアカウント設定削除動作** [高]
  - 正しいパスとDELETEメソッドによるリクエストが200または204ステータスで正常完了すること
  - DELETE以外のHTTPメソッド（GET/POST/PUT等）でリクエストした際、405 Method Not Allowedが適切に返却されること
  - 認証・認可ポリシーが「不要」に構成されている場合に、トークンを付与しないアクセスで動作が成立すること
- **ITV-L3-038 Wi-FiプロファイルXMLのスキーマ検証動作** [中]
  - WLAN_profile_v1.xsdに基づく正常なXML文字列を送信した際、検証結果（正常）がHTTP 200で返ること
  - WLAN_profile_v1.xsdスキーマ定義に合致しない不正なXML（必須タグ欠落等）を送信した際、400 Bad Requestまたはバリデーションエラーとなること
  - XML以外の平文テキストや極端に巨大なサイズ、または空データを送信した際、プログラムが強制終了せず適切な400系エラーに制御されること

#### ITV-L2-030 HTTPメソッド・パラメータ検証 (自動応答ファイル生成API群)

- **ITV-L3-042 AppLockerポリシー適合性検証 (POST /api/validators/applocker-policy)** [高]
  - 送信されたAppLockerPolicyXmlがAppLocker.xsdスキーマ定義に合致する場合、検証成功レスポンスが返却されること
  - スキーマに合致しない不正なXMLを入力した際、ConfigurationExceptionを模した適切なエラーコードおよび検証失敗メッセージが返却されること
  - AppLockerPolicyXml内の改行コードがCRLFに正規化されて処理されること
- **ITV-L3-043 自動応答ファイルXMLプレビュー生成 (POST /api/generator/xml/view)** [高]
  - システム要件回避フラグ(BypassRequirementsCheck)、ネットワークバイパス(BypassNetworkCheck)、簡易設定(ExpressSettings)等のパラメータが正しく結合され、意図通りのXML(autounattend.xml)が生成・中継されること
  - 追加コンポーネントのXMLマークアップ構文が無効な場合、ConfigurationExceptionをハンドリングしてエラー応答を返すこと
  - 生成されるXML内の特殊文字がxml_node.jsの定義に基づき、XML文字エスケープまたはASCII以上の文字エンティティに変換されていること

#### ITV-L2-031 同時実行制御 (サーバーサイド API 生成機能)

- **ITV-L3-044 並行処理・CORS・容量負荷検証** [中]
  - 複数クライアントから同一API(POST /api/generator/xml/view 等)へ同時にリクエストが行われた際、スレッドの競合やメモリリークなく並行してautounattend.xmlが組み立てられること
  - HTTP OPTIONSメソッド（プリフライトリクエスト）に対し、CORSヘッダー「Access-Control-Allow-Origin: *」が正常に返却されること
  - 極端に大容量のAppLockerPolicyXmlを送信した場合でも、APIサーバーがプロセスダウンせず、バッファ上限やバリデーションエラーとして処理されること

#### ITV-L2-034 HTTPメソッド・パラメータ解析 (サーバーサイド API を介した自動応答ファイル生成機能)

- **ITV-L3-048 GETメソッドによるクエリパラメータ抽出** [高]
  - GETリクエストのURLSearchParamsからパラメータが正しく一括抽出できること
  - 抽出したパラメータ値に基づき自動応答ファイル(autounattend.xml)が正しくビルドされること
  - プロセッサアーキテクチャ(ProcessorArchitecture)パラメータが存在しない場合に既定値が適用されること
